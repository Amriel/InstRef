# InstRef

[English](README.md) · повний посібник українською

Десктопний застосунок, який сканує твої збережені пости в Instagram — і загальні
(«All Posts»), і кожну підбірку окремо — качає відео/фото в обрану папку та
одразу імпортує їх в Eagle, розкладаючи по папках за назвами підбірок.

---

## Вікно

Бічна панель, один розділ — одна тема: **Огляд** (стан сесії, Eagle і моделі,
останній запуск, черга, журнал, кнопка «Синхронізувати»), **Синхронізація**
(підбірки, що качати, обхід, лайки та фільтр), **Перегляд**, **Модель**,
**Eagle**, **Акаунт** (сесія, захист акаунта, розклад), **Обслуговування**,
**Про застосунок**. Усередині розділів — підвкладки. Налаштування зберігаються
самі при переході між розділами.

У «Про застосунок» — кнопка **«Оновити»**: встановлений застосунок качає
інсталятор із релізу на GitHub і запускає його; запуск із вихідників качає
архів релізу, замінює код, не чіпаючи налаштувань, бази, сесії й словника,
оновлює залежності й перезапускається.

## Швидкий старт

1. **`install.bat`** — один раз. Створює `.venv` і ставить залежності
   (потрібен Python 3.10+ з опцією «Add python.exe to PATH»).
2. **`InstRef.bat`** — запуск застосунку.
3. Вкладка **«Сесія»** → «Знайти сесію» або встав `sessionid` вручну → «Перевірити».
4. Вкладка **«Синхронізація»** → «Оновити підбірки» → познач потрібні → **«Синхронізувати»**.

## Як він отримує доступ до акаунта

Пароль ніде не зберігається. Використовується cookie `sessionid` — та сама сесія,
під якою ти вже залогінений у браузері.

* **Автоматично.** Кнопка «Знайти сесію» читає кукі з Firefox, LibreWolf, Brave,
  Vivaldi, Opera, Chromium, Chrome, Edge.
* **Вручну.** Chrome та Edge на Windows 11 шифрують кукі так, що сторонні програми
  їх не читають (App-Bound Encryption). Тоді: `F12` → **Application** → Cookies →
  `https://www.instagram.com` → скопіюй значення `sessionid` у поле на вкладці «Сесія».
* **З файлу.** Кнопка «З файлу cookies.txt…» читає експорт у форматі Netscape.

Сесія лежить у `session.json` поруч із застосунком і діє, доки ти не вийдеш
з акаунта в тому браузері.

## Що і куди зберігається

За замовчуванням усі медіафайли лягають **в одну папку**, а структура за
підбірками відтворюється **всередині Eagle** — так один пост, що є у двох
підбірках, не дублюється на диску.

```
<папка завантаження>/
├── 2026-08-21_studioalt_Знімали цей таймлапс три ночі поспіль.mp4
├── 2026-08-21_formnorm_Мʼяке світло у ранковій кухні_01.jpg   ← слайди каруселі
├── 2026-08-21_formnorm_Мʼяке світло у ранковій кухні_02.mp4
├── _thumbnails/                            ← обкладинки відео (.jpg)
└── _metadata/                              ← повні дані поста (.json, якщо увімкнено)
```

Назва береться з підпису поста: перший змістовний рядок без хештегів, згадок,
посилань та емодзі, обрізаний по межі слова. Якщо тексту в пості нема —
підставляється код поста, як раніше. Шаблон налаштовується:

| Токен | Що підставляє |
|---|---|
| `{title}` | початок підпису; без тексту — код поста |
| `{user}` | автор без `@` |
| `{date}` `{time}` | дата й час поста |
| `{code}` `{id}` | код і числовий id поста |
| `{type}` | `reel` / `video` / `photo` / `carousel` |
| `{collection}` | назва підбірки |

Якщо у двох різних постів вийде однакова назва, другий отримає суфікс `_2` —
чужий файл ніколи не перезаписується.

### Опис і автор всередині файлу

Типово підпис, автор, дата, посилання й хештеги записуються **в сам медіафайл**,
без окремого `.json` поруч. ffmpeg для цього не потрібен.

* **Відео (.mp4)** — теги у стилі iTunes: назва, виконавець (`@автор`),
  коментар з повним підписом і посиланням, дата, жанр, ключові слова, альбом
  з назвою підбірки. Видно у VLC, mpv, MPC, Eagle і у властивостях файлу Windows.
* **Фото (.jpg)** — EXIF: `Artist`, `ImageDescription`, `DateTimeOriginal`,
  `Copyright` з посиланням, а також XP-поля (`XPTitle`, `XPComment`, `XPAuthor`,
  `XPKeywords`) — саме їх показує вкладка «Подробиці» у провіднику Windows.

Окремий `.json` з повними даними (лайки, перегляди, тривалість, музика) можна
увімкнути галочкою «Ще й окремим .json» — вони не виключають одне одного.

Якщо в налаштуваннях обрати **«Підпапка на кожну підбірку»** — файли розкладуться
по теках з назвами підбірок; спільні пости копіюються, а не качаються двічі.

## Пролайкане і фільтр мемів

Окрема підбірка **«Пролайкане»** зʼявляється у списку поруч зі збереженими —
вмикається галочкою в розділі «Пролайкане».

**Ліміт перегляду.** Типово застосунок дивиться лише **50 найсвіжіших**
пролайканих за запуск. Це не примха: `Максимум нових за запуск` рахує
*завантажені* пости, а відсіяні меми його не збільшують — тож у стрічці лайків,
повній мемів, той ліміт не спрацьовував ніколи і обхід тягнувся через усю
історію. Ліміт «Дивитись останніх» рахує саме переглянуті пости. 0 — без обмеження.

Фільтр мемів працює **тільки для пролайканого**: збережене ти куруєш сам,
тож там усе качається як є. Оцінка будується на хештегах, імені акаунта,
тривалості відео та позначці платної співпраці:

* **мем** — пропускається, у базі лишається помітка, щоб не оцінювати щоразу;
* **арт або реклама** — качається;
* **порівну ознак** — їде в теку `_review` і у вкладку **«Ревʼю»**.

### Візуальна модель (LM Studio)

Правила судять за текстом, а «мем це, арт чи ігровий ролик» — питання візуальне.
Тому пости показуються локальній візуальній моделі. Вона бачить **не обкладинку,
а сам ролик**: із відео дістається кілька кадрів, рівномірно розкиданих по всій
тривалості (краї підрізаються). Обкладинка reels — це часто чорний кадр або
титр, і саме судження за нею давало найбільше помилок. Карусель модель бачить
по слайдах.

Кількість — поле **«Кадрів на відео»**, від 1 до 60, типово 6. Понад 12 кадрів
контексту вистачає не кожній локальній моделі, тому застосунок про це попереджає
і сам здрібнює кадри, щоб запит не розпух:

| Кадрів | Сторона кадру |
|---|---|
| 1–12 | 640 px |
| 13–24 | 512 px |
| 25–40 | 448 px |
| 41–60 | 384 px |

Модель повертає три речі:

* **категорію** — мем, арт, реклама, гра, інше (це рішення про полицю, не тег);
* **опис** англійською, до 80 слів, у стилі режисерської нотатки: суб'єкт,
  оточення, світло й колір, техніка виробництва;
* **теги** — виключно зі словника (див. нижче).

Опис і теги вшиваються всередину самого файлу (поле «Коментар» у mp4, XPComment
та XPKeywords у jpg) і їдуть у нотатку та теги Eagle — поруч із підписом автора.

**Карусель описується по слайдах.** Ролик — це одна річ, і кілька його кадрів
дають один опис. А слайди каруселі — різні картинки, тож кожен іде окремим
запитом і отримує власний опис та власні теги. Спільний текст на всі був би
неправдою про кожен із них.

### Словник тегів

Головна причина, чому бібліотека з часом перестає шукатись, — теги-синоніми.
`3d-render`, `3drender`, `render` і `3d` — це чотири різні теги для Eagle, і
жоден із них не знайде решту. Тому модель не вигадує теги, а **обирає зі
словника**: близько тридцяти категорій із фіксованими списками — світло,
колір, крупність, ракурс, оптика, рух камери, монтаж, композиція, техніка,
матеріали, середовище, тварини, транспорт, продукти, поведінка, естетика.

Просити модель дотримуватись списку недостатньо — вона все одно щось вигадає.
Тому словник **застосовується кодом** після відповіді:

* усе, чого немає у списках, відкидається;
* близькі промахи виправляються (`skiing` → `sport-action`, `goldfish` → `fish`,
  `3D Render` → `3d-animation`);
* взаємовиключні теги не стоять поруч (`handheld` + `locked-off`, `hard-light` +
  `soft-light`, `cgi` + `3d-animation`) — лишається той, що модель назвала першим;
* ліміт на категорію не дає одному аспекту заглушити решту;
* для нерухомої картинки категорії руху й монтажу не застосовуються взагалі;
* останнім тегом завжди йде `autotagged` — за ним видно, де модель уже була.

**Словник росте сам, але свідомо.** Відкинутий тег не зникає: він рахується, і
коли модель наполягає на ньому N разів (типово 5), він з'являється у
**«Пропозиції до словника»** (Налаштування → Модель). Там видно, скільки разів
модель його просила, і одним кліком тег додається в обрану категорію — або
відхиляється назавжди. Так словник наростає по твоєму реальному контенту, а не
по фантазіях моделі.

Самі списки лежать у `taxonomy.json` поруч із `config.json` — файл можна правити
руками (категорії, ліміти, синоніми). Оновлення застосунку його не чіпає.

### Стара бібліотека

Синхронізація описує лише **нові** пости. Те, що зібралось раніше, лишається без
описів — а якщо папку завантажень чистили, самі файли лишились узагалі тільки
всередині Eagle. Для цього є кнопка **«Описати бібліотеку моделлю»**
(Налаштування → Додатково):

* читає елементи з теки застосунку в бібліотеці Eagle і бере кадри з них;
* дописує опис і теги до наявних елементів, не створюючи дублікатів;
* пропускає те, у чому вже є рядок `Опис:`, тож повторний запуск дешевий;
* зупиняється будь-коли, і зроблене лишається зробленим.

Кожен файл — окремий запит до моделі, тож на кількасот елементів піде не одна
година. Кнопка спершу пропонує спробувати на двадцяти.

Вмикається в розділі **«Модель»**. Потрібно: у LM Studio завантажити візуальну
модель (qwen2.5-vl, llava, moondream — будь-яку з підтримкою зображень) і
увімкнути сервер: **Developer → Start Server**. Кнопка «Перевірити» покаже
завантажені моделі.

**Що з чим:**

| Підбірка | Що робить модель |
|---|---|
| Збережене й підбірки | Тільки описує й проставляє теги. Судити не судить, у Eagle йде одразу |
| Пролайкане | Судить: «мем» і «гра» відсіює, «арт» і «реклама» лишає, «інше» віддає тобі |

Ролик, який модель дивилась, качається **один раз**: він завантажується у
тимчасову теку `_cache` заради кадрів, а потім просто переїжджає на місце.

Нижче заданої впевненості рішення моделі не приймається — пост іде в ревʼю.
Якщо сервер не запущений, застосунок пише про це в журнал і працює за правилами.

**Інструкція для моделі** — редаговане поле в тому ж розділі. У ній доступні
`{frames}` (скільки кадрів надіслано) і `{kind}` (reel / video / carousel /
photo). Відповідь має лишатись JSON із полями `category`, `confidence`,
`description` і `tags`. Кнопка «Повернути типову» скасовує правки; поки
інструкцію не змінено, вона оновлюється разом із застосунком.

**Яку модель брати.** Для цієї задачі — `Qwen3-VL-4B-Instruct` (~3.5 ГБ VRAM у Q4).
Бери саме **Instruct**, не **Thinking**: «думальні» варіанти витрачають сотні
токенів на міркування перед відповіддю, а нам потрібен JSON. Кілька кадрів плюс
опис — це довше за одну обкладинку, тому типовий таймаут підняли до 120 с.

Порівняти моделі на **своїх** кадрах:

```
.venv\Scripts\python.exe bench_vision.py --limit 12
```

Завантаж у LM Studio кілька моделей одночасно — скрипт прожене всі й покаже час
на кадр і де вони розійшлись у відповідях.

## Черга перегляду

Метод свідомо приблизний: надійного сигналу «це мем» в Instagram немає. Тому
нічого не зникає мовчки — усе, що вирішено не тобою, спершу проходить перед
очима. Черга одна; походження показує позначка на картці:

* без позначки — правила не змогли вирішити, рішення цілком за тобою;
* «◆ модель: качати» — вона схвалила, файл уже в основній теці й чекає згоди
  на Eagle;
* «◆ модель: пропустити» — вона відсіяла, файл у `_review` і буде видалений,
  коли погодишся. Відсіяне свідомо не видаляється одразу: ролик уже
  завантажений заради кадрів, а помилкове «мем» інакше було б не спіймати.
* «схоже на вже наявний пост @…» — репост того, що вже є в бібліотеці, за
  відбитком кадрів.

Спершу в списку йде те, що модель зібралась викинути: помилкове «мем» коштує
втраченого поста, а помилкове «арт» — лише зайвого файлу.

На картці — кадрострічка ролика, опис і теги моделі в **редагованих полях**
(теги з автодоповненням зі словника): виправив тут — у Eagle піде виправлене.
Зірка ★ позначає опис як зразок: кілька таких підставляються в інструкцію
моделі, і наступні описи рівняються на них.

Клавіатура: стрілки — рух по картках, `Y` — залишити, `N` — не качати,
`O` — відкрити файл, `S` — зірка. Над сіткою — згода з моделлю у відсотках
по категоріях: це і є її справжня точність.

Кнопка **«Погодитись з моделлю»** розбирає її рішення одним кліком: схвалене
йде в Eagle, відсіяне видаляється; пости без позначки не чіпає.

### Кнопки на картці



| Дія | Що робить |
|---|---|
| Залишити / Врятувати | Переносить файли з `_review` до основної папки і лише тоді веде в Eagle |
| Не качати / Погоджуюсь | Видаляє файли. Автора ніяк не позначає — буває, що пост просто не потрібен |
| Завжди | Те саме, що «Залишити», плюс акаунт у білий список |
| Ніколи | Видаляє й додає акаунт у чорний список |

Подвійний клік по превʼю відкриває сам файл у системному плеєрі. Одночасно
показується не більше 60 карток — решта підтягується по мірі того, як ти
розбираєш чергу.

Списки акаунтів мають пріоритет над усіма правилами — саме вони з часом
дають точність, бо один клік закриває цілий акаунт назавжди.

## Eagle

**InstRef — конвеєр, Eagle — база.** Eagle зберігає власну копію кожного
імпортованого файлу, тож папка завантажень — лише перевалка. Галочка
«Видаляти локальні копії після імпорту» (розділ Eagle) прибирає її
автоматично: видаляється тільки те, що вже підтверджено видно в бібліотеці,
памʼять зберігається — дублі не качаються, черга перегляду не чіпається.


**Один пост — один елемент.** Eagle на кожен імпорт *копіює* файл, тож пост,
який лежить і в збережених, і в лайках, і в іменованій підбірці, ставав двома-
трьома окремими елементами бібліотеки. Типово застосунок імпортує пост один
раз; галочку можна зняти, якщо копії по папках потрібні свідомо.

Якщо дублікати вже накопичились — кнопка **«Знайти дублікати в Eagle»**
(Налаштування → Додатково) знаходить їх за адресою поста й показує список.
Видаляє тільки після окремої згоди, і навіть тоді лише переносить у кошик
Eagle. Найстаріша копія кожного поста лишається — саме в неї могли потрапити
твої правки. Карусель дублікатом не вважається: це різні файли одного поста.


Eagle має локальний API на `http://localhost:41595`, який працює, поки програма
запущена. Застосунок:

* створює кореневу папку (типово **Instagram Saved**);
* усередині — по папці на кожну підбірку;
* до кожного файлу додає назву (перший рядок підпису), посилання на оригінальний
  пост, повний підпис в анотацію і теги: `instagram`, `@автор`, тип
  (`reel` / `photo` / `carousel`), назву підбірки та хештеги з підпису.

Кнопка **«Перевірити зв'язок»** на вкладці налаштувань покаже версію Eagle
й активну бібліотеку. Якщо Eagle закритий — синхронізація однаково пройде,
файли просто залишаться на диску.

## Налаштування

Розкладені по п'яти розділах у лівій колонці — гортати нічого не треба.

**Завантаження**

| Опція | Що робить |
|---|---|
| Папка | Куди складати медіафайли |
| Структура | Усе в одну папку / підпапка на кожну підбірку |
| Качати | Відео · фото та каруселі · прев'ю |
| Опис і автор | вшивати у сам файл · додатково окремим .json |
| Шаблон імені | `{title}` `{user}` `{date}` `{time}` `{code}` `{type}` `{id}` `{collection}` |
| Пропускати більші за | Ліміт розміру файлу в МБ (0 — без обмеження) |

**Сканування**

| Опція | Що робить |
|---|---|
| Лише нове | Пропускає те, що вже завантажено |
| Стоп після N | Зупиняє обхід підбірки після N відомих постів поспіль — саме це робить щоденний запуск швидким |
| Максимум нових за запуск | Обмежує обсяг однієї сесії |
| Пауза | Затримка між сторінками; **не знижуй без потреби** — це головний захист від блокування |
| Мережа | Таймаут і кількість повторів |
| Проксі | `http://user:pass@host:port`, якщо потрібно |

**Eagle** — увімкнення, адреса API, коренева папка, підпапки на підбірки,
які теги додавати.

**Автозапуск** — задача у Планувальнику завдань Windows:
щодня, кожні N годин, щотижня або при вході в систему. «Запустити зараз»
виконує її негайно, у фоні.

**Поведінка застосунку** — запуск разом із Windows, старт згорнутим у трей,
синхронізація одразу після запуску, згортання в трей замість виходу,
сповіщення після завершення.

**Додатково** — таймаут, повтори, проксі та обслуговування:

* **Оновити назви й метадані наявних файлів** — перейменовує вже завантажене
  за поточним шаблоном і дописує опис та автора всередину. Нічого не перекачує:
  підписи беруться з локальної бази й з файлів у `_metadata`. Прев'ю та `.json`
  їдуть слідом за своїм файлом.
* **Ярлик на робочому столі** — щоб запускати не через `.bat`, а звичайним
  ярликом з іконкою.
* **Забути історію завантажень** — файли лишаються, але наступний запуск
  вважатиме всі пости новими.
* **Скинути налаштування** — повертає типові значення; сесія зберігається.

## Якщо щось пішло не так

**«Немає доступної сесії Instagram», хоча в браузері ти залогінений**

Це найчастіший випадок, і лог виглядає приблизно так:

```
Firefox: Failed to find Firefox cookie file
Google Chrome: This operation requires admin. Please run as admin.
✖ Немає доступної сесії Instagram.
```

Читається він так:

* рядки про Firefox / Brave / Opera — ці браузери просто не встановлені;
* рядок про Chrome чи Edge — сесія там **є**, але Windows 11 шифрує сховище кукі
  ключем, прив'язаним до самого браузера. Повідомлення про адміністратора
  оманливе: запуск від адміна це **не** обходить;
* останній рядок — про `session.json` поруч із застосунком, а не про браузер.

Рішення разове: відкрий застосунок → вкладка **«Сесія»** → встав `sessionid`
(F12 → Application → Cookies → `https://www.instagram.com`) → «Перевірити».
Далі фонові запуски беруть сесію з `session.json` і до браузера не звертаються.

**Фоновий запуск нічого не зробив, а я не помітив**

Кожен запуск пише результат у `last_run.json`. Якщо він був невдалим,
застосунок при наступному старті показує червоний банер угорі вкладки
«Синхронізація». Задача з планувальника додатково показує системне вікно,
яке саме зникає через 25 секунд (вимикається прапорцем `--no-popup`).

Перевірити сесію без повного запуску:

```
.venv\Scripts\python -m igsaved.cli --check
```

**Instagram відхилив сесію**

Сесія помирає, якщо вийти з акаунта в тому браузері, звідки її взято, або
змінити пароль. Просто встав свіжий `sessionid` на вкладці «Сесія».

## Робота без вікна

```
sync.bat                          тиха синхронізація (її ж використовує планувальник)
.venv\Scripts\python -m igsaved.cli --list           показати підбірки та їхні id
.venv\Scripts\python -m igsaved.cli --sync --full    повний обхід замість «лише нове»
.venv\Scripts\python -m igsaved.cli --sync --limit 50 --no-eagle
.venv\Scripts\python -m igsaved.cli --sync --collection ALL_MEDIA_AUTO_COLLECTION
```

Логи — у `logs/sync_РРРР-ММ.log`.

## Структура проєкту

```
igsaved/
├── config.py       налаштування (config.json)
├── session.py      пошук sessionid у кукі браузерів
├── instagram.py    підбірки та посторінковий обхід збережених
├── downloader.py   завантаження з CDN: ретраї, .part-файли, ліміт розміру
├── naming.py       безпечні для Windows імена + шаблони
├── state.py        SQLite: що завантажено, де лежить, що вже в Eagle
├── eagle.py        клієнт локального API Eagle
├── sync.py         оркестратор одного проходу
├── tagging.py      теги всередині mp4 (mutagen) і jpg (piexif)
├── scheduler.py    Планувальник завдань + автозапуск із Windows
├── status.py       підсумок останнього запуску для банера в GUI
├── notify.py       системне вікно при збої фонового запуску
├── cli.py          headless-режим
└── ui/             інтерфейс на PySide6
tests/              юніт-тести (pytest)
```

Робочі файли, які створюються поруч: `config.json`, `session.json` (секрет),
`device.json`, `state.db`, `last_run.json`, `logs/`.

## Про обережність

Instagram не має публічного API для збережених постів, тому застосунок
звертається до тих самих внутрішніх ендпоінтів, що й сайт, під твоєю сесією.
Це працює, але формально суперечить умовам користування, а Instagram уміє
помічати автоматизацію — не за обсягом, а за **темпом**: рівні короткі
інтервали й повторні входи. Тому застосунок:

* не робить два проходи частіше, ніж раз на 6 годин (ручний запуск питає
  підтвердження), і ніколи два одночасно;
* починає плановий прохід із випадковим зсувом до 20 хвилин;
* перевикористовує сесію замість свіжого входу щоразу;
* тримає паузи 8–15 с між сторінками — краще не зменшувати;
* на відповідь «зачекай кілька хвилин» зупиняє **весь** прохід і не
  повертається добу — навіть за ручним запуском;
* після трьох невдач на одному пості (видалений, приватний) більше його не
  чіпає; список — у «Додатково», звідки їх можна повернути.

Перший повний прохід великої бібліотеки варто робити з лімітом («Максимум
нових за запуск», напр. 200) за кілька заходів; щоденний запуск за розкладом
у режимі «лише нове» — найспокійніший сценарій. Якщо Instagram відхилив
сесію, просто онови `sessionid` на вкладці «Сесія».

Файл сесії на Windows зашифровано DPAPI (читається лише під твоїм обліковим
записом), база резервується щотижня і перед кожною міграцією (`backups/`),
журнали старші за три місяці прибираються, а раз на добу застосунок питає
GitHub, чи є нова версія.

Качай лише те, що зберіг для себе, і поважай авторів — на референси корисно
лишати посилання на оригінал, воно вже є в метаданих і в полі `website` в Eagle.
