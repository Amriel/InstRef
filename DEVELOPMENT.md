# InstRef — документ розробки

Внутрішній опис проєкту: як він влаштований, чому влаштований саме так, які
помилки вже зроблені й чим вони закінчились. `README.md` — для того, хто
користується; цей файл — для того, хто продовжує писати код.

Версія на момент запису: **2.2.0** · 174 тести · ~12 600 рядків коду.

> **Цей документ оновлюється разом із кодом — завжди, у тій самій зміні.**
> Він описує застосунок таким, яким той є зараз. Документ, який відстав від
> коду, гірший за його відсутність: відсутньому не вірять, а застарілому
> вірять. Правила й чек-лист — у `CLAUDE.md`, розділ 14 нижче — коротко.

## 1. Що це

Застосунок збирає збережені й пролайкані пости Instagram, кладе їх у папку та
в бібліотеку Eagle, вшиває опис і автора всередину самих файлів, а візуальна
модель у LM Studio дивиться на кадри й пише опис та теги з контрольованого
словника.

**Межа продукту:** InstRef — конвеєр, а не бібліотека. Instagram → фільтр →
опис → теги → Eagle. Базою є Eagle: він зберігає власну копію кожного файлу,
у ньому шукають і ним діляться. Тому тут немає і не буде власного пошуку,
власної вкладки-галереї чи довгого зберігання вихідників — папка завантажень
лише перевалка, яку застосунок уміє прибирати за собою.

Три речі, які визначили архітектуру:

1. **Instagram не має публічного API для збереженого.** Використовується
   `instagrapi` — обгортка над приватним мобільним API. Звідси: sessionid
   замість пароля, паузи між сторінками, обережність із кількістю запитів.
2. **Eagle на кожен імпорт копіює файл.** Це не бібліотека посилань. Тому
   «додати той самий пост ще й у папку лайків» = друга копія на диску, а не
   друга полиця. Півпроєкту крутиться навколо цієї властивості.
3. **Користувач працює наосліп.** Він не бачить логів, поки не відкриє їх.
   Тому головний принцип нижче.

## 2. Головний принцип: жодних тихих відмов

Це не стиль, а наслідок болю. Кожна друга проблема в цьому проєкті виглядала
однаково: застосунок нічого не зробив і нічого не сказав.

| Що мовчало | Як виглядало для користувача |
|---|---|
| Кукі Chrome зашифровані App-Bound Encryption | «сесії є, а воно не бачить» |
| Eagle запущений, але імпорт вимкнено галочкою | «0 файлів пішло в ігл» |
| Візуальна модель не піднялась через прапорець | «просто додалось в ревью, не відправилось моделі» |
| Запуск за розкладом упав без вікна | тиша, ніяких файлів |
| Порожній опис збережено й заблокував повтор | «на частину відео взагалі опису не робить» |

**Правило:** якщо гілка коду веде до «нічого не робимо» — там має бути
`self.log(...)` з причиною. Не `return None`. Приклади в коді:
`_setup_vision()`, `_setup_eagle()`, `_describe()`, `describe_library()`.

Друге правило звідти ж: **порожній результат не зберігається**. Порожній опис
у `ai_meta` виглядав як «вже описано» і назавжди закривав повторну спробу.

## 4. База даних

SQLite, WAL. Схема в `state.py::SCHEMA`.

| Таблиця | Ключ | Навіщо |
|---|---|---|
| `media` | `pk` | статус поста: pending / done / archived / skipped |
| `files` | `path` | що саме лежить на диску, з номером слайда |
| `membership` | `(media_pk, collection_pk)` | у яких підбірках бачили пост |
| `eagle_items` | `(media_pk, collection_pk)` | що вже пішло в бібліотеку |
| `collections` | `pk` | назви й лічильники підбірок |
| `review` | `media_pk` | черга на рішення + `source`: rules / model |
| `ai_meta` | `(media_pk, idx)` | опис і теги від моделі, окремо на кожен слайд |
| `tag_candidates` | `tag` | теги поза словником: скільки разів модель просила |
| `runs` | autoincrement | історія запусків |

### Статуси `media` — головна логіка «не качати двічі»

```
pending  → щойно побачили, ще не завантажили
done     → завантажено, файли мають бути на диску
archived → завантажено, файли СВІДОМО прибрані чисткою папки
skipped  → свідомо не качаємо (мем / відхилено в ревʼю)
```

`is_known(pk)`:

* `archived` → **True без перевірки диска**. Файлів навмисно немає, і питати
  диск означало б качати все заново після кожної чистки.
* `done` → True тільки якщо файли реально на місці. Це запобіжник на випадок,
  коли користувач випадково стер файл.

Різниця між цими двома рядками — те, заради чого існує кнопка «Очистити папку
завантажень»: вона видаляє файли й ставить `archived`, зберігаючи памʼять.

### Міграції

`CREATE TABLE IF NOT EXISTS` не змінює вже створену таблицю. Тому
`_add_missing_columns()`:

* дописує нові стовпці через `ALTER TABLE` (`review.source`);
* перезбирає таблицю, коли змінився первинний ключ (`ai_meta` переїхала з
  `(media_pk)` на `(media_pk, idx)` — ALTER цього не вміє).

Обидві міграції перевірені на реальній базі з кількома сотнями постів, а не
лише на порожній — саме там вилазять несподіванки.

## 5. Потік синхронізації

```
run()
 ├─ ig.connect(sessionid)
 ├─ _setup_eagle()              ← каже вголос, якщо Eagle є, а імпорт вимкнено
 ├─ _setup_vision()             ← каже вголос, якщо модель пропущено
 └─ для кожної підбірки:
     _sync_collection(col)
      └─ для кожного поста:
          ├─ ліміт перегляду?            → стоп
          ├─ is_skipped / is_known?      → пропуск (+ дозалив у Eagle)
          ├─ _judge(media, col)          → лише для ЛАЙКІВ
          │   ├─ classify.classify()     → правила за текстом
          │   └─ _ask_vision()           → лише для сумнівних
          └─ _process_media()
              ├─ collect_assets → завантаження (або переїзд із _cache)
              ├─ _describe()             → опис і теги, якщо увімкнено
              ├─ _embed()                → метадані всередину файлу
              └─ черга Eagle  АБО  черга перегляду
```

### Темп запитів — головний захист акаунта

`instagrapi` працює через приватне мобільне API, і Instagram виявляє
автоматизацію. Виявляє не за обсягом, а за **темпом**: рівні короткі інтервали
й повторні входи виглядають як скрипт, бо людина так не гортає.

Після реального попередження від Instagram («підозріла активність, підозра в
автоматизації») зроблено три речі:

1. **Запобіжник частоти.** `min_hours_between_runs` (типово 6). `run()`
   відмовляється працювати, якщо попередній прохід був щойно — і каже про це
   вголос. Запуск за розкладом просто пропускається; ручний питає
   підтвердження, бо людина має право наполягти свідомо.
2. **Перевикористання сесії.** `connect()` спершу пробує профіль із
   `device.json`: якщо збережений `sessionid` того самого акаунта й у профілі
   є `authorization_data`, робиться один дешевий `account_info()` замість
   повного `login_by_sessionid` (кілька запитів). Десяток свіжих входів на
   добу був найпомітнішим слідом.
3. **Спокійніші паузи.** 2–5 с → 8–15 с між сторінками, 0.4 → 1.0 с між
   завантаженнями. Міграція піднімає їх тим, хто не редагував.

Чого тут свідомо **немає** і не буде: підробки відбитків пристроїв,
імітації людських патернів, ротації проксі. Це вже обхід захисту платформи,
а не акуратне користування. Єдиний чесний важіль — звертатись рідше.

### Ліміти обходу

`max_items_per_run` рахує **завантажене**. У стрічці лайків, повній мемів, він
не спрацьовував ніколи — відсіяне не збільшує лічильник, і обхід тягнувся через
усю історію. Тому окремо є `liked_scan_limit` / `scan_limit`, які рахують
**переглянуте**.

### Кадри й `_cache`

Обкладинка reels — часто чорний кадр або титр. Судити за нею про ролик було
головним джерелом помилок класифікації. Тому:

1. Сумнівний ролик качається наперед у `<downloads>/_cache/<pk>.mp4`.
2. `frames.extract()` бере N кадрів рівномірно по тривалості (краї підрізає).
3. Модель бачить усі кадри одним запитом.
4. Якщо пост схвалено — файл **переїжджає** з `_cache` на місце
   (`Path.replace`, той самий диск, миттєво). Другого завантаження немає.

`_prefetch: Dict[url, Path]` звʼязує ці кроки; `_download_or_reuse()` перевіряє
кеш першим ділом. Хвости прибирає `_clear_cache()` у `finally`.

Кількість кадрів — 1..60. Понад 12 кадри автоматично здрібнюються
(`frames.side_for()`), бо 60 кадрів по 640 px — це мегабайти base64 й десятки
тисяч токенів контексту.

## 6. Черга перегляду

Спершу черг було дві — «Ревʼю» й «Рішення моделі». Виявилось, що це один
інструмент, розрізаний навпіл: дії над обома чергами однакові, а дві вкладки з
тими самими двома кнопками лише змушували перемикатись. Злито в одну.

Походження не зникло — воно лишилось у колонці `review.source` і показується
позначкою на картці:

| `source` | Позначка | Що це означає |
|---|---|---|
| `rules` | немає | правила не змогли вирішити, рішення цілком за тобою |
| `model` | ◆ модель: качати | схвалено, файл в основній теці, чекає згоди на Eagle |
| `model` | ◆ модель: пропустити | відсіяно, файл у `_review`, буде видалений |

Механіка спільна: **Залишити** = перенести з `_review` до основної теки +
відправити в Eagle; **Не качати** = видалити файл + `mark_skipped`. Для рішень
моделі змінюються лише написи («Врятувати» / «Погоджуюсь»).

Кнопка «Погодитись з моделлю» виконує її пропозиції гуртом і свідомо **не
чіпає** записи з `source = rules`: модель їх не бачила, і вирішувати за неї
було б підміною.

**Чому відсіяне моделлю все одно завантажується.** Ролик уже лежить у `_cache`
після перегляду кадрів — покласти його в `_review` коштує нуль трафіку. Зате
помилкове «мем» стає видимим і його можна врятувати. Помилкове «мем» коштує
втраченого поста, помилкове «арт» — зайвого файлу, тому в списку відсіяне йде
першим.

У Eagle не потрапляє нічого, що чекає рішення: `is_pending_review()`
перевіряється і в синхронізації, і в дозаливі.

## 7. Візуальна модель

LM Studio, OpenAI-сумісний HTTP. Ніяких нових залежностей.

### Що повертає модель

```json
{"category": "art", "confidence": 0.87,
 "description": "One paragraph, English, under 80 words",
 "tags": ["close-up", "neon-lit", "..."],
 "why": "max 8 words"}
```

`category` — рішення про полицю (мем/арт/реклама/гра/інше), окреме від тегів.

### Розбір відповіді

`parse_answer()` витримує: обгортку ```` ```json ````, текст навколо, фігурні
дужки **всередині опису** (`_first_json_object()` рахує дужки з урахуванням
рядків — регекс тут не годиться), відсутній JSON узагалі (тоді шукає назву
категорії словом), невідому категорію (опис і теги все одно повертає — вони
не винні).

### Контрольований словник

Головна причина, чому бібліотека перестає шукатись, — синоніми: `3d-render`,
`3drender`, `render`, `3d` — чотири різні теги для Eagle.

`taxonomy.py` — 29 категорій, 367 тегів, 39 синонімів, 8 груп несумісних тегів.
Списки підставляються в інструкцію через `{taxonomy}`.

**Ключове рішення: словник не просять дотримувати — його застосовують.**
`Taxonomy.normalize()` після відповіді моделі:

* приводить до вигляду (`Close-Up` → `close-up`);
* мапить промахи (`skiing` → `sport-action`, `goldfish` → `fish`);
* викидає все, чого немає у списках;
* прибирає несумісні пари (`handheld` + `locked-off` — лишається перший);
* тримає ліміт на категорію;
* для нерухомої картинки не застосовує категорії руху й монтажу;
* дописує `autotagged` останнім.

Інструкцію модель порушує; цю перевірку — ні.

**Словник росте, але свідомо.** Відкинутий тег не зникає — `tag_candidates`
рахує його. Після N повторів (типово 5) він зʼявляється в діалозі
«Пропозиції до словника»: видно, скільки разів модель просила, і одним кліком
тег додається в обрану категорію. Так словник наростає по реальному контенту,
а не по фантазіях моделі.

Файл `taxonomy.json` лежить поруч із `config.json`, правиться руками і **не
входить у zip оновлення** — інакше апдейт затирав би правки.

### Плейсхолдери інструкції

`{frames}`, `{kind}`, `{mode}`, `{taxonomy}`. Підставляються `str.replace`, а
**не** `str.format`: інструкцію редагує людина, і зламана фігурна дужка не має
валити синхронізацію.

Порожній `vision_prompt` у конфізі = «взяти вбудовану». Так оновлення
застосунку покращує інструкцію тим, хто її не чіпав, і ніколи не затирає
чужу правку. Той самий трюк — з `taxonomy.json` і `LEGACY_TEMPLATES`.

## 8. Eagle

Локальний API на `http://localhost:41595`, живий поки програма відкрита.

**Eagle копіює файл на кожен `addFromPaths`.** Це джерело найдовше не поміченого
бага: пост, який лежить і в збережених, і в лайках, імпортувався двічі й ставав
двома елементами з двома копіями відео. Тому `eagle_one_item_per_post` типово
увімкнено, а `is_in_eagle(pk)` без підбірки відповідає «чи є будь-де».

`find_eagle_duplicates()` шукає вже накопичене за адресою поста. Карусель
дублікатом не вважає (різні файли одного поста — різні `name`). Видаляє тільки
після окремої згоди й лише в кошик; найстаршу копію лишає, бо саме в неї могли
потрапити правки користувача.

### Прибирання перевалки

`eagle_delete_local_after_import` (типово вимкнено): наприкінці проходу
локальні копії вже імпортованих постів видаляються, пост стає `archived` —
памʼять лишається, дублі не качаються. Два запобіжники:

* видаляється лише **підтверджене** — те, що реально видно в бібліотеці
  (звірка за адресою поста через `item/list`), бо копіювання на боці Eagle
  асинхронне і власна позначка «відправлено» ще не означає «лежить»;
* мовчання Eagle ≠ відсутність файлів: не вдалось отримати список — нічого
  не видаляється. Черга перегляду не чіпається ніколи.

Оскільки після чистки папки завантажень файли лишаються **тільки в Eagle**,
`describe_library()` бере кадри звідти: `library/info` → шлях бібліотеки,
`item/list` → елементи, `<library>/images/<id>.info/` → сам файл (шукаємо за
розширенням, бо Eagle нормалізує імена).

## 9. Метадані всередині файлів

Користувач попросив: «в метаданні самого відео, а не в окремий файл».

* **mp4** — iTunes-атоми через `mutagen`: `©nam`, `©ART`, `aART`, `©cmt`,
  `desc`, `ldes`, `©day`, `©gen`, `keyw`, `©alb`, `purl` і
  `----:com.apple.iTunes:URL`. Посилання дублюється в кілька полів, бо різні
  програми читають різні.
* **jpg** — EXIF через `piexif` плюс XP-поля Windows (`XPTitle`, `XPComment`,
  `XPAuthor`, `XPKeywords`) у UTF-16LE з нульовим завершенням — інакше
  провідник їх не показує.

Помилка запису тегів **ніколи** не валить завантаження: у гіршому разі файл
лишається без тегів, і про це є рядок у журналі.

## 10. Журнал помилок

Найцінніша частина документа: кожен пункт — реальна помилка, її причина й що
з неї слідує.

| Симптом | Корінь | Урок |
|---|---|---|
| «додало відео по грі, навіть на ревʼю не відправило» | `"art" in "gamestart"` — підрядок | Порівнюй **токени**, не підрядки (`classify.name_hit`) |
| «при відкритті ревʼю мільярд вікон і комп висне» | `resizeEvent` → `reload()` → зміна розміру → рекурсія; `mousePressEvent` відкривав файл | Перекладання з дебаунсом, смуга прокрутки завжди на місці, подвійний клік + кулдаун |
| «слайдер в самий низ улітає» | повна перебудова сітки на кожен клік | `_drop_card()` — прибрати одну картку, зберегти позицію |
| «1 постів · 2101 файлів» | `totals()` не рахував `archived` | Статус ≠ «не існує» |
| Модель мовчки не викликалась | Умова вимагала `sync_liked`, а підбірку обрали галочкою в таблиці | Не привʼязуй логіку до прапорця, який має другий шлях уводу |
| «на частину відео опису не робить» | Описувались лише НОВІ пости; бібліотека зібрана раніше | Будь-яка нова обробка потребує способу догнати старе |
| Опис із `frames=1` на відео | Нерозібране відео йшло моделі як `image/jpeg` цілим mp4 | Перевіряй тип файлу перед відправкою (`shots_from_file`) |
| «постійно одні і ті ж відоси підкачує» | Синхронізація ключувала імпорт за `pk` підбірки, обслуговування — за **назвою** | Один ключ на всю систему. Назва — для людини, pk — для коду |
| Тести зависли на 2 хв | Фейкові медіа пішли по справжніх URL | Стабай мережу в тестах явно |
| `unzip -o` на змонтованій теці | Монтування забороняє видалення | Розпакувати в `/tmp`, потім `cat` поверх |
| Кнопки спінбоксів як биті квадрати | Стилізація Qt | Прибрати кнопки зовсім (`width:0`) |
| Instagram надіслав попередження про автоматизацію | 15 проходів за 2 доби, деякі за 2 хв один від одного, кожен зі свіжим входом | Обмежувати не обсяг, а **темп**: запобіжник частоти + перевикористання сесії |
| `.bat` не запускались після подорожі через Linux | Git і `cat` лишали LF | `.gitattributes` (`*.bat eol=crlf`) — правило замість памʼяті |
| Git показав зміненими геть усі файли на диску користувача | Монтована тека віддає все як 0700, git читає це як зміну режиму | `git config core.fileMode false` у такому репозиторії |
| Дві вкладки перегляду з тими самими кнопками | Розділив за походженням запису, а не за дією над ним | Вкладки діляться за тим, що людина **робить**, а не звідки взялись дані |

**Метапатерн:** майже всі баги — це «дві частини системи по-різному розуміють
одне поняття». Ключ підбірки (pk vs назва), статус файлу (немає на диску vs
не завантажено), тип медіа (відео vs картинка), порожній результат (немає vs
не питали).

## 10a. Збірка й поширення

Застосунок роздається як `InstRef-Setup.exe`; збирає його GitHub Actions на
`windows-latest`, бо .exe для Windows можна зібрати лише у Windows.

* `entry.py` — єдина точка входу зібраного бінара. `--sync` веде в `cli`,
  решта — у GUI. Один .exe замість двох свідомо: PySide6 з opencv важать
  ~400 МБ, і другий бінар подвоїв би інсталятор заради самої лише консолі.
* `InstRef.spec` — one-folder, не one-file: одинарний .exe розпаковував би ті
  ж 400 МБ у temp при кожному запуску. UPX вимкнено — ламає підпис Qt і
  дратує антивіруси. Зайві модулі Qt виключені (WebEngine, QML, 3D, charts).
* `installer/InstRef.iss` — Inno Setup, установка **на користувача**: без UAC,
  бо все, що застосунок пише, і так лежить у профілі.
* `.github/workflows/release.yml` — тег `v*` → тести → збірка → інсталятор і
  портативний zip у реліз.

**Специфікацію перевірено збіркою на Linux** (`pyinstaller InstRef.spec`).
Windows-бінара так не отримати, але це ловить головне, заради чого спека й
пишеться: прихований імпорт, якого бракує. Зібраний застосунок запускався в
обох режимах — `--sync` повернув очікуваний код 2 «немає сесії», GUI підняв
вікно. Розмір ~390 МБ: PySide6 99 МБ, opencv 67 МБ, numpy 42 МБ.

**Головна тонкість зібраної версії.** Встановлений застосунок лежить у Program
Files, куди користувач писати не може. Тому шляхи розділені:

* `resource_dir()` — те, що поставляється з застосунком (іконка, скрипти).
  У PyInstaller це `sys._MEIPASS`.
* `app_dir()` — куди писати. У зібраній версії `%APPDATA%\InstRef`, у
  вихідниках — корінь проєкту, як і було.

Плутанина між ними означала б застосунок, який падає при першому ж збереженні
налаштувань.

## 10b. Що застосунок зберігає локально

Жоден із цих файлів не належить репозиторію — усі вони в `.gitignore`:

| Файл | Що всередині | Чому чутливо |
|---|---|---|
| `session.json` | cookie `sessionid` | **повний доступ до акаунта Instagram** |
| `config.json` | налаштування, токен Eagle, проксі | проксі буває з логіном і паролем |
| `device.json` | відбиток пристрою для instagrapi | привʼязаний до сесії |
| `state.db` | pk, підписи, посилання, шляхи на диску | історія того, що ти зберігав |
| `logs/` | журнали запусків | імена акаунтів і назви файлів |

`sessionid` ніде не потрапляє в журнал: у коді фігурує лише сам факт його
наявності. Але журнал містить імена авторів і назви постів, тож перед тим як
вкласти його в issue, варто переглянути.

## 11. Розробка

```bash
python -m pytest tests/ -q        # 163 тести, ~13 с
python -c "import compileall; compileall.compile_dir('igsaved', quiet=1)"
```

GUI перевіряється безголово:

```bash
QT_QPA_PLATFORM=offscreen python твій_скрипт.py
```

Обовʼязково підмінити `config.CONFIG_PATH` і `STATE_PATH` на тимчасові — інакше
тест напише в робочі файли проєкту.

### Стиль тестів

Тести названі твердженнями про поведінку, а не про функції:
`test_skipped_post_takes_its_temporary_video_with_it`, а не `test_drop_prefetch`.
Кожен тест на виправлений баг містить у докстрінгу **симптом**, щоб через
півроку було зрозуміло, що саме він охороняє.

### Доставка на машину користувача

```bash
zip -rq update.zip . -x "*.pyc" "*__pycache__*" "taxonomy.json"
# → SendUserFile → device_commit_files у _update.zip
# → розпакувати в /tmp, cat поверх файлів (монтування блокує видалення)
# → CRLF для .bat
# → mv _update.zip _archive/IG_Saved_Sync_vN.zip
```

`.bat` **мусять** мати CRLF — інакше Windows їх не виконає.
`taxonomy.json` і `config.json` ніколи не входять в архів.

## 13. Роадмап

> Уточнено 2026-08-24 разом із межею продукту: **InstRef — конвеєр, Eagle —
> база**. З попередньої версії роадмапу викреслено все, що будувало б другу
> бібліотеку поруч із першою: вкладку «Бібліотека», FTS-пошук, семантичний
> пошук на ембедингах, XMP для Adobe. Пошук — робота Eagle; наша робота —
> щоб йому було чим шукати: чисті теги зі словника й чесні описи.

Аналіз реальної бази (437 постів, 66 записів ai_meta) показав:

* **описано 5% бібліотеки** — бекфіл ручний і багатогодинний, тому стоїть;
* **confidence моделі — константа 0.95**: поріг мертвий, калібрування через
  промпт для малих моделей не працює; чесне калібрування — згода людини;
* **66 записів зроблено до появи словника** — брудні теги вже в Eagle,
  а збережене в ai_meta ніде не проганяється через нормалізацію повторно;
* **черга перегляду збанкрутувала**: 132 закрито гуртом, 12 розібрано;
* **`cinematic` у половині записів** — перевикористаний тег нічого не знаходить.

### Спринт 1 — міцність (захист акаунта й даних)

- [ ] Міжпроцесний замок: GUI і планувальник не мають працювати одночасно
- [ ] Rate-limit: `PleaseWaitFewMinutes`/429 → обірвати ВЕСЬ прохід, кулдаун 24 год
- [ ] Джитер у CLI: випадкові 0–20 хв перед плановим проходом
- [ ] Бекап `state.db`: перед міграцією + тижнева ротація (тримати 5)
- [ ] DPAPI-шифрування session.json на Windows (ctypes, без залежностей)

### Спринт 2 — конвеєр, який сам себе доводить до кінця

- [x] Прибирання перевалки після підтвердженого імпорту (v2.2.0)
- [ ] Нічний бюджет описів: після планової синхронізації описувати N елементів
      бібліотеки (`describe_library(limit=N)` вже вміє) — покриття росте само
- [ ] Ретро-нормалізація: прогнати збережені теги ai_meta через словник і
      виправити вже імпортовані елементи Eagle (`update_item`, без моделі)
- [ ] Синоніми зі спостережених промахів: backlight→backlit,
      photography→photograph, motiongraphics→motion-graphics,
      blackandwhite→black-and-white, minimalist→minimalist-composition

### Спринт 3 — перегляд, який не банкрутує

- [ ] Кадрострічка на картці відео (frames.extract уже є)
- [ ] Опис і теги моделі на картці
- [ ] Клавіатурний трияж: стрілки + Y/N
- [ ] Агрімент-статистика: зберігати (модель сказала / людина вирішила),
      точність по категоріях — єдине чесне калібрування замість confidence

### Пізніше

- [ ] Переописання сильнішою моделлю (колонка `model` вже є; кадри читаються
      зі сховища Eagle, локальні файли не потрібні)
- [ ] Перцептивні дублікати перед імпортом: dHash кадрів, Гемінг ≤ 8
- [ ] Звіт словника: перевикористані (>40%) і мертві (0 ужитків) теги
- [ ] Перевірка нової версії через GitHub Releases API + банер
- [ ] Розбити main_window.py на pages/*.py; tests на файли; ruff у CI
- [ ] Whisper-транскрипція туторіалів (важка залежність, опційно)

### Свідомо не робимо

* Власний пошук/галерею — база в Eagle, і крапка.
* Імітацію людських патернів, підробку відбитків, ротацію проксі — обхід
  захисту платформи. Єдиний чесний важіль — рідше.
* Перейменування пакета `igsaved` → `instref`: зламає все, цінність нуль.

**Відомі обмеження**: кукі Chrome/Edge за App-Bound Encryption — sessionid
руками; describe_library — один запит на файл, години на сотні елементів;
дублікати в Eagle шукаються лише за адресою поста.

## 14. Правило супроводу цього документа

Повний чек-лист — у `CLAUDE.md`, який читається автоматично на початку роботи
в теці проєкту. Тут — суть.

**Будь-яка зміна коду завершується оновленням цього файлу, у тій самій
зміні.** Не наприкінці спринту й не «як буде час»: документ, який відстав від
коду, шкідливіший за відсутній, бо йому вірять.

| Зробив | Онови тут |
|---|---|
| Нову можливість | розділ + рядок у таблиці версій |
| Виправив баг | **рядок у журналі помилок** (розділ 10) |
| Новий модуль | карту модулів (розділ 3) |
| Нову таблицю чи стовпець | базу даних (розділ 4) + опис міграції |
| Змінив потік роботи | схему у відповідному розділі |
| Додав поле конфігу чи тег | цифри в шапці й у розділі 7 |

**Журнал помилок наповнюється з кожного виправлення.** Три частини, і всі три
обовʼязкові: як це виглядало для користувача, у чому була справжня причина,
який урок. Рядок без урока — марний.

Числа в шапці й тексті мають бути перевірені, а не переписані по памʼяті:

```bash
python - <<'PY'
import sys; sys.path.insert(0, '.')
from dataclasses import fields
from igsaved.config import Config
from igsaved.taxonomy import Taxonomy
tax = Taxonomy()
print("полів конфігу:", len(fields(Config)))
print("категорій:", len(tax.categories), "тегів:", len(set(tax.all_tags())),
      "синонімів:", len(tax.aliases), "груп несумісних:", len(tax.exclusive))
PY
python -m pytest tests/ -q | tail -1
wc -l igsaved/*.py igsaved/ui/*.py tests/*.py | tail -1
```
